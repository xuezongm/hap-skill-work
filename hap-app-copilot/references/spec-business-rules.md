## 一、 业务规则定位与 3 类核心设计场景

业务规则在表单加载（`onLoad`）及字段值发生变化（`onChange`）时实时在前端触发计算，适用于新建表单和记录详情页。在系统建模与修改时，主要覆盖以下 3 类业务场景：

1. **动态显隐与联动录入**：
   - 示例：当【业务类型】选择“其他”时，动态显示【补充说明】字段；
   - 示例：当【是否需要发票】勾选时，动态展开【发票抬头】与【纳税人识别号】分段；
2. **条件只读保护与动态必填**：
   - 示例：当【单据状态】为“已归档”或“审批中”时，将表单核心业务字段设为只读，锁定修改；
   - 示例：当【审批结果】为“已拒绝”时，强制将【拒绝原因】设为必填；
3. **业务规则校验与防错拦截 (error_prompt)**：
   - 示例：当【报销金额】> 50,000 元时，在表单底部显示红色错误提示并阻止提交；
   - 示例：当【实际结束时间】早于【实际开始时间】时，弹出逻辑错误提示并拦截保存。

## 二、 触发条件语法与操作符 (Conditions)

### 2.1 条件组逻辑结构
条件采用标准的嵌套树形结构：
- **外层容器**：`type: "group"`, `logic: "AND" | "OR"`
- **子条件**：`children: [ { type: "condition", field: "<alias或ID>", operator: "<操作符>", value: <比较值> } ]`

### 2.2 支持的操作符清单 (`operator`)

| 操作符 | 语义说明 | 适用字段类型 | value 格式要求 |
|---|---|---|---|
| **`eq`** | 等于 | 文本、数值、日期、SingleSelect | 字符串 / 数字 |
| **`ne`** | 不等于 | 文本、数值、日期、SingleSelect | 字符串 / 数字 |
| **`in`** | 包含于（多选一） | SingleSelect, MultipleSelect, Dropdown | **数组** `["值1", "值2"]` |
| **`not_in`** | 不包含于 | SingleSelect, MultipleSelect, Dropdown | **数组** `["值1", "值2"]` |
| **`gt`** | 大于 | 数值、金额、日期 | 数字 / 日期字符串 |
| **`gte`** | 大于等于 | 数值、金额、日期 | 数字 / 日期字符串 |
| **`lt`** | 小于 | 数值、金额、日期 | 数字 / 日期字符串 |
| **`lte`** | 小于等于 | 数值、金额、日期 | 数字 / 日期字符串 |
| **`is_null`** | 为空 | 全字段类型 | `null` (无需传 value) |
| **`not_null`** | 非空 | 全字段类型 | `null` (无需传 value) |
| **`contains`** | 文本包含 | Text, RichText | 字符串 |

> [!CAUTION]
> **多值匹配避坑铁律**：对同一个选项字段匹配多个可能值时，**必须使用单个 `in` 条件 + value 数组**。严禁拆成多个 `eq` 条件用 `AND` 逻辑连接（逻辑上单字段不可能同时等于两个互斥值，导致规则永远不触发）。

## 三、 执行动作类型 (Actions)

当满足触发条件时，系统执行 `actions` 数组中定义的动作：

| 动作类型 (`type`) | 作用对象 (`controls` / `message`) | 行为说明与业务效果 |
|---|---|---|
| **`show`** | 字段 / Divider 别名数组 | 满足条件时**显示**指定字段/分段，否则自动隐藏 |
| **`hide`** | 字段 / Divider 别名数组 | 满足条件时**隐藏**指定字段/分段 |
| **`readonly`** | 字段别名数组 | 满足条件时将指定字段设为**只读锁定**（禁止用户手动修改） |
| **`readonlyAllFields`** | **无需传 fields** | 满足条件时将当前表单的**所有字段一键设为只读锁定**（全表只读场景首选） |
| **`editable`** | 字段别名数组 | 满足条件时将字段恢复为**可编辑**状态 |
| **`required`** | 字段别名数组 | 满足条件时将字段设为**必填**（空值时前端拦截提交） |
| **`optional`** | 字段别名数组 | 满足条件时将字段恢复为**选填（非必填）** |
| **`error_prompt`** | 文本提示内容 (`message`) | 满足条件时在表单底部显示**警示文案并彻底阻止表单保存/提交** |

## 四、 安全与防冲突设计原则

1. **唯一字段标识规范**：
   - 规则中的 `field` 与 `controls` 优先使用规范的字段别名（如 `biz_status`）；若无别名则使用真实的 24 位物理 `controlId`；
2. **避免逻辑冲突与死锁**：
   - 同一个字段严禁在不同规则中配置互斥动作（例如规则 A 设为 `required`，规则 B 同时设为 `hide` 会导致用户无法填写也无法提交的逻辑死锁）；
3. **Divider 分段级联收起**：
   - 当对一个 `Divider` 分割线字段执行 `hide` 动作时，明道云表单会自动联动收起该 Divider 下辖的整个视觉区块。

## 五、 终态锁定 (lock) 与 全表只读 (readonlyAllFields) 选型准则

| 维度 | 🔒 锁定规则 (`ruleType: "lock"`) | 📝 交互规则全表只读 (`actionType: "readonlyAllFields"`) |
|---|---|---|
| **核心定位** | **记录终态物理封存** | **表单输入动态只读** |
| **删除操作** | 🚫 **彻底锁死删除记录**（用户无法删除该记录） | ✅ **用户仍可删除记录**（拥有删除权限时） |
| **前台视觉** | 顶部显示**系统锁头图标 + 提示说明** (`lock.message`) | 表单内输入框置灰，无锁头提示 |
| **条件要求** | ⚠️ **单一 condition 对象**（仅限 SingleSelect/MultipleSelect/Checkbox） | ⚙️ **group 条件组**（支持全字段类型与多条件组合） |
| **典型场景** | 单据已审批/已归档/已结单，防止任何篡改与删除 | 外部系统同步流水、查看模式表单、或仅限制字段输入 |
