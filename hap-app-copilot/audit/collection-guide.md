# Audit 证据采集指南

本文档只说明 Audit 如何用当前 MCP 能力取得足够证据。检查规则、严重度和评分只在 `audit-checks.md` 定义；流程和报告只在 `workflows/audit.md` 定义。

## 一、核心原则

1. 先锁定检查项，再读取证据。
2. 优先读取能回答问题的最轻结果；证据充分即停止。
3. 返回格式不等于证据完整程度。目录、结构摘要和对象详情必须按实际接口能力区分。
4. 全量审查保证检查项覆盖，不等于调用所有接口或读取全部业务数据。
5. 默认采用关键抓取：关键表首轮直接读取结构 DSL，其余表在预算内先读结构 MD；详情只读取核心、高风险或已命中的对象。
6. 失败与通过使用不同停止条件：一个确定反例足以判失败；判通过必须覆盖检查项声明的完整范围。
7. 定向对象由主 Agent直接按需读取；全量和定维度才考虑批量采集。
8. AI 补充观察默认复用正式检查已经取得的证据，不为丰富报告而扩大采集范围。
9. 单次运行受统一取证预算约束；覆盖不完时保留缺口，不以增加调用换取表面上的完整结论。
10. 每次工具返回在当前会话中即时分析，提取 `facts` 所需字段和值后丢弃原始返回；不落盘为默认行为。

## 二、三类证据

### 1. 对象目录

用于定位 ID、名称、说明和对象类型，不用于判断内部配置。

`get_app_worksheets_list(responseFormat="md")` 当前返回工作表的 `id`、`name`、`remark` 和 `displayType`。它不能直接说明：

- 是否存在 Formula、Lookup、Rollup 或 Relation；
- 哪张表确定属于明细、流水或日志；
- 哪张表确定存在性能问题。

AI 可以根据名称和说明提出快速筛查候选，但完整审查不得据此排除对象。

### 2. 结构摘要

`get_worksheet_structure(responseFormat="md")` 适合批量分析：

- 字段 ID、名称、类型、必填、标题字段；
- 选项、基础数据来源和关联目标；
- Formula、Lookup、Rollup、Relation 等字段是否存在；
- 视图 ID、名称和类型。

结构摘要可能包含较长选项或说明，但通常仍比结构 DSL 更适合普通表的初步判断。它不保证包含布局、高级字段配置、完整公式、视图筛选排序或存储策略。

### 3. 深度结构与对象详情

两个工作表接口用途不同：

- `get_worksheet_structure(responseFormat="dsl")` 返回字段与关系的标准 DSL，用于布局 `span`、完整公式、关联配置、`storeData` 等结构级判断；
- `get_worksheet_settings` 返回工作表基础信息、表单显示、提交行为和分享权限，用于标签页、封面、提交按钮、提交后动作和连续录入等设置级判断。

其他检查项需要精确配置时，读取相应 JSON 或详情接口，例如：

- 完整表单布局和高级字段属性；
- 公式、汇总和 `storeData`；
- 视图显示列、筛选、排序、查询方式和快捷操作；
- 角色权限详情；
- 页面组件和图表详情；
- 已发布工作流节点结构。

DSL 与工作表设置互补，不能互相替代，也不存在单个"完整配置"接口。始终以实际返回字段能否支持当前检查为准。

## 三、按模式采集

### 全量审查

- 执行全部检查项。
- 先按检查项合并证据需求。
- 取得应用、工作表及选中检查项需要的其他对象目录，据此识别首轮关键表。
- 关键表直接读取结构 DSL；其余相关表在单次取证预算内按优先级读取结构 MD。DSL 已提供所需结构时，不再为同一张表读取 MD。
- 根据普通表 MD 中出现的复杂公式、汇总、关联中心、核心状态流转或其他检查命中，将该表提升为关键表并补读 DSL。
- 工作表设置、视图、已发布流程、高权限角色和默认页面等详情，仅在检查项需要时读取。
- 先形成初步状态；若评分门槛尚未满足，在剩余预算内依次补齐未评估的 P0、影响完成门槛的 P1。预算耗尽、无法取得或继续读取没有判断价值时停止并保留 `not_evaluated`。
- 默认不读取生产记录、讨论、审批实例或运行日志。

首轮关键表按以下顺序识别，满足任一项即可，不要求全部满足：

1. 用户明确指定的表；
2. 应用目录中承载审批、工单、订单、合同等主业务过程的表；
3. 被已发布工作流直接触发或作为核心读写对象的表；
4. 主导航中的核心业务入口表；
5. 已知涉及敏感数据、高数据量或高权限操作的表。

仅凭名称无法确定时先按普通表读取 MD，不猜测为关键表；MD 显示其为关联中心或复杂计算承载表后再提升。

### 定向维度审查

- 执行该维度全部检查项。
- 根据这些检查项覆盖必要对象，不能由 AI 任意缩减检查项。
- 例如要把完整性能检查判为通过，必须取得所有相关表的字段结构，不能仅根据表名挑选候选表；若对象数量超过单次预算，则本次只能输出 `incomplete` 和未覆盖范围，结构 DSL、视图和工作流详情仍按具体性能检查项读取。

### 定向对象或 finding

- 主 Agent直接执行，不派发子 Agent。
- 已知对象 ID 时直接读取目标；只有名称时才调用列表定位。
- 定向审查的目标工作表视为关键表，首轮直接读取结构 DSL；finding 复查若已明确只需视图、规则或其他非结构证据，可以跳过结构读取。
- 只读取当前检查需要的关联部分，不把一个关联对象扩展成新的全量审查。

### 定向资产类别

- 先读取该类资产的完整目录，确认总数和状态分布。
- 详情优先读取线上有效、核心业务、高风险和结构命中的对象；发现确定反例即可判定相应检查失败。
- 要对该资产类别判定某项检查全部通过，必须读取该检查要求的全部相关详情；关键对象未发现问题不能代表全类通过。
- 只读取完成目标资产检查所需的直接依赖，不扩展为应用其他资产的全量审查。
- 工作流类别审查先读取全部工作流列表，再读取已发布核心流程、审批流程、Webhook/子流程及命中异常候选的流程详情。工作流列表可以支持数量、状态、名称和描述等目录级判断，不能支持节点、分支、鉴权和 I/O 合并等详情级 `pass`。

### 快速筛查

- 可以只读应用和对象目录，并由 AI 选择少量候选对象读取结构摘要。
- 结果必须声明部分覆盖，不得给出正式评分或"未发现问题"的完整结论。

## 四、各类对象的读取规则

### 应用与导航

- 已知 `appId` 时无需再次通过应用列表搜索。
- 需要应用描述、导航分组或入口配置时调用 `get_app_info`。
- 表目录只调用一次；同一轮不要同时获取 MD 和 JSON 两种格式。

### 工作表与字段

- 枚举工作表：`get_app_worksheets_list(responseFormat="md")`。
- 首轮关键表：调用 `get_worksheet_structure(responseFormat="dsl")`，即时分析后记录来源和关键字段。
- 其余相关表：调用 `get_worksheet_structure(responseFormat="md")`，即时分析后记录来源和关键字段。
- DSL 已成功返回时，不再为同一张表调用 MD；普通表后续提升为关键表时，可以在已有 MD 基础上补读一次 DSL。
- 涉及表单显示、标签页、封面、提交行为或分享权限时，调用 `get_worksheet_settings`；它不能替代结构 DSL。
- 涉及 `CHK-PRF-005`（唯一标识去重）或 `CHK-PRF-008`（大表检索加速）时，调用 `get_worksheet_index_list`。
- 对象 ID 已知的定向审查可直接读取目标结构，避免应用级扫描。

补抓只针对缺失的证据类型：已有有效 DSL 时补工作表设置或其他详情，不重复调用 DSL。接口调用失败可以重试一次；返回有效但缺少所需字段时，改用对应补充接口或记为 `not_evaluated`，不得重复请求同一接口碰运气。

### 视图

- 工作表结构摘要提供视图 ID、名称和类型。
- 只有检查显示列、筛选、排序、查询后生效、自定义动作入口等配置时，才逐个读取相关视图详情。
- 关键抓取优先默认视图、核心业务视图和结构命中的高风险视图。确定反例可直接判失败；要对全部相关视图判通过，仍须取得完整范围证据。
- 定向视图审查应读取该视图详情，并按需读取所属表结构。

### 业务规则

- 对每张相关表调用一次 `get_business_rule_list`。
- 列表返回已经包含规则详情，直接使用。
- 不逐条调用详情接口，不做额外验证或补采。
- 接口调用失败时，相关检查记为 `not_evaluated`。

### 自定义动作

- 只有选中的检查项涉及动作语义、图标、触发条件或视图入口时才读取。
- 需要核对执行逻辑时，继续读取绑定工作流；不审查无关工作流。

### 打印模板

- `CHK-BIZ-011`、`CHK-BIZ-012` 和 `CHK-SEC-016` 需要打印模板证据。
- 对相关表调用打印模板列表或详情接口。
- 需要判断视图绑定、在线编辑和下载权限时，必须读取支持这些字段的模板配置；平台不可见则记为 `not_evaluated`。

### 工作流

- 先读取工作流列表定位目标。
- 详情优先读取已发布的核心流程、高风险流程和被检查对象直接引用的流程。列表只能证明目录级事实，不能证明节点级检查通过。
- 审查线上有效逻辑时明确读取已发布版本，不得以默认草稿代替。
- 审批节点或子流程节点返回内部流程 ID 时，只有当前检查需要完整节点逻辑才继续读取对应内部流程。
- 默认不读取运行实例和日志；相关检查需要运行事实时才按范围读取或转人工核验。

### 角色与权限

- 先读取角色列表。
- 只有安全检查、角色工作台或字段权限检查需要时才读取角色详情，优先高权限、普通生产角色和命中敏感对象的角色。
- 单个角色未发现问题不能证明全部角色权限合规；需要全局通过时必须覆盖全部相关角色。
- 敏感字段判断需要表结构和角色权限共同作为证据。

### 自定义页面与图表

- 选中的检查项涉及页面布局、工作台、帮助入口或图表配置时才读取。
- 先取清单或页面结构，优先默认入口、核心工作台和命中候选；只有指标、维度和筛选关系需要精确判断时再读取图表详情。

### 业务数据

默认不读取业务记录。只有用户明确要求数据质量审查，或检查项明确需要记录量、样本或运行事实时，才读取最小必要统计或样本，并在报告中说明范围。

## 五、取证预算与停止条件

### 单次运行硬上限

- 工作表结构接口合计最多调用 **50 次**，其中 DSL 最多 **10 次**；MD 后补 DSL、失败重试都分别计次。
- 其他对象级详情接口合计最多调用 **30 次**，包括工作表设置、视图、业务规则、动作、模板、工作流、角色、页面和业务数据；失败重试也计次。
- 依赖只展开到目标对象的一层直接依赖；依赖读取和补抓使用同一预算，不另设额外额度。
- 应用信息和每类对象目录只读取一次，不计入对象级预算。

达到上限后不自动继续下一批，也不临时提高额度。已取得的确定反例仍可判失败；若需要完整覆盖才能判通过的检查项仍有缺口，则改记 `not_evaluated`，并在 `results.json` 和报告中记录预算用量、覆盖数量和剩余数量。只有用户明确要求继续或缩小范围后，才开始新的有界运行。

### 即时分析与按需归档

- 每次接口成功返回后，在当前会话中即时分析，提取检查所需的字段路径和值，记入 `sources`（来源元数据）和 `facts`（关键字段与观察值）。原始返回默认不保存。
- 多个检查项共用同一次工具返回时，在结果中引用同一个 `sourceId`，不重复调用。
- `archive` 模式时，将触发升级的相关原始返回保存到 `evidence/`，路径记录在 `sources[sourceId].rawPath`。文件命名使用"对象名称--对象 ID 末 8 位"；名称中的特殊字符替换为 `-`。

### 停止条件

- 发现与规则直接对应的确定反例后，可停止同一检查项的继续读取并判为 `fail`；需要聚合影响范围时可以继续。
- 只有检查项声明的必要范围已完整覆盖时，才能停止并判为 `pass`；关键对象或抽样未发现问题时记为 `not_evaluated`。
- 只有证据证明业务前提不存在时才能判为 `not_applicable`。
- 平台不可见或调用失败时记为 `not_evaluated`；不得通过无关接口猜测结果。
- 未能形成结论的检查项填写 `missingEvidence`，不得把说明文字写进 `facts` 或 `sourceIds`。

## 六、AI 补充观察的取证边界

- 先完成 `CHK-*` 映射；能对应现有检查项的问题必须按该检查项处理，不能降级为不计分观察。
- 观察必须引用本次运行 `sources` 中已记录的直接证据来源，默认不额外调用接口。
- 只有疑似存在显著安全、数据破坏或核心业务中断风险，且一次最小读取即可验证时，才允许为观察补充取证；否则标记需要业务确认。
- 只输出与用户目标和当前应用直接相关、具有明确影响和可执行建议的观察，不输出通用套话、纯主观审美或无证据猜测。
- 观察不影响检查状态、覆盖率、风险和评分，也不能自动触发修改。

## 七、批量并行的边界

子 Agent只在全量或定维度审查数据量较大、宿主支持并且并行有实际收益时使用。派发内容应是独立的证据采集任务，例如一组工作表结构或一组已发布工作流。

每个子 Agent必须：

- 只读取指定对象和证据；
- 返回成功对象、失败对象和提取的关键事实清单；
- `archive` 模式时按命名规则写入 `evidence/`；`compact` 模式不写入文件；
- 不评分、不生成 finding、不扩大范围、不派发下级 Agent。

不创建任务回执文件；完成情况以返回清单为准。
