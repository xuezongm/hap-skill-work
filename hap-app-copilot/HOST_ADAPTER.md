# 本地宿主适配

本文统一定义宿主环境下的 MCP 工具 Schema 核实、规则渐进加载、子代理任务包读取与异常自愈边界。入口、工作流与构建任务引用本文件；业务授权、`tools_count >= 170` 全量工具门禁及构建并发分工按对应工作流规则严格执行。

## 工具定义与文件读取

- **开工前必查实时 MCP Schema（唯一能力真值源，严禁未查先降级）**：
  - **真值源定位**：Skill 中的 `references/hap-*.md` 与 `modify_guide.md` 仅提供业务建模原则与高频防坑约束，**绝非平台参数全集**；**当前连接环境的实时 MCP 工具 Schema 才是判断平台支持哪些子能力与合法参数结构的唯一权威真值源**。
  - **正确执行顺序（先看 Schema 再定改法）**：在确定具体技术方案或动手开工前，**必须先查阅目标 MCP 写工具的实时 Schema**（Eager 环境直接核对内联工具定义；Lazy 环境如 `call_mcp_tool` 必须先读取对应的 `<toolName>.json` Schema 文件，单行超长 Schema 若发生字节截断则用 `ByteOffset` 续读或按目标控件/节点类型名精准提取对应子定义）。
  - **严禁主观断定不支持而绕路**：只要实时 MCP Schema 支持对应原生参数（例如 `Rollup` 的 `config.relationFilter` 条件汇总、`Relation` 的 `resultFilter` 等），必须优先采用原生能力并结合真实表结构主动补全合理过滤口径；**绝对禁止仅因 Skill 文档未提及，在未查实时 MCP Schema 前就主观认定“平台不支持”并擅自降级为普通字段 + 绕路工作流**，也严禁跳过 Schema 凭印象盲猜入参。
- **文档简写与 `appId` 必传铁律**：文档中的 `tool_name(...)` 均为重点业务参数示意简写。除 `get_org_list`、`get_org_detail`、`get_app_list`、`create_app`、`find_member`、`find_department`、`get_current_user` 等少数全局/组织级接口外，**所有应用内读写接口（即使已传全局唯一的 `worksheet_id` / `workflow_id` / `page_id` / `role_id` / `chatbot_id`）调用时必须始终显式传入当前目标 `"appId"`**；遇到 `10001` 或单点 `401` 报错时，第一时间核查是否漏传 `"appId"` 或写错参数键名。
- **按场景分层读取规则**：
  - **Modify 场景**：优先运行 `scripts/resolve_context.py --mode modify --assets {domain1,domain2} --render` 一次性加载裁剪后的公共底线与目标领域规则；仅在构造复杂底层参数时按需点读 `references/hap-*.md` 对应章节。
  - **Data 场景**：完整读取 `workflows/data.md`，遵循其中的视图平铺与降维取数准则、分级确认门禁、`fields[].type` 防坑规则及审批/PBP 流转规范。
  - **Build 子代理场景**：Subagent 首轮必须完整读取 `prepare` 预编译生成的 `bundleFiles`（`.build/task-bundles/{taskId}*.md`，单卷已控制在单次读取上限内，内联了步骤 SOP、专属 `taskContext` 与必读领域规范全文），**严禁仅用 `grep` 搜索代替阅读**；`sourceFiles` 仅在异常恢复或核对跨表补充细节时按需查阅，正常执行不扫描无关表或他表回执。

## 自主排查与恢复

- **职责边界与排查工具**：执行中遇到参数、连接、文件读取或脚本错误时，结合真实反馈自行诊断修正；未检测到 HAP MCP 时按 [MCP 接入指南](MCP_SETUP.md) 引导配置。构建步骤中的 `allowedTools` 规定了该原子任务的写入职责白名单，执行者**不得越权调用其他步骤的业务写入工具**破坏并发分工，但在排查异常或核实线上状态时可按需调用只读查询工具，始终锁定已选环境与当前目标 `appId`。
- **异常回读防重**：超时、断流或返回契约异常导致写入结果未知时，**必须先调用只读接口核实线上实际状态**，已成功创建或发布的部分严禁重复重放，只续作未完成部分。
- **局部缺口如实收口**：单次接口报错或局部校验未过时，优先基于原始规则和线上配置定点修复；确因外部数据缺失（如指定人员/签名不存在）或平台限制无法自动闭环时，保留已成功结果并在回执或总结中如实记录具体缺口，不扩大权限、不虚报完成。

## 用户交互

- 需要用户做选择时，优先调用宿主当前模式可用的原生结构化提问工具；工具名、字段、单轮问题上限和推荐标记严格遵循宿主真实定义，不捏造不存在的参数，互不依赖的问题在宿主允许范围内合并提问。
- 需要多选时使用宿主原生多选参数；宿主仅支持单选时通过自由输入或分题表达多选；无结构化提问工具时回退简短文本列表。
- 推荐选项置于首位并使用宿主约定的推荐前缀；宿主自带自由输入项时不重复添加“其他”。
- 正文仅用 1～2 句话说明必要背景，不重复罗列提问卡片中的题目与选项；必须等待用户实际提交选择后才执行依赖该答案的写操作。
